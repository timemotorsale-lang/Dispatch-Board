# COO Workbook Operating Philosophy

Status: supplemental source of truth

Purpose: define why the COO Workbook exists, what kind of behavior it should encourage, and how the backend intelligence must support staff without turning the workspace into surveillance.

## Core Intent

The COO Workbook is a daily execution workspace first. Reports, scorecards, carryovers, and manager summaries are outputs of good daily use, not the reason staff open the page.

The workspace should help the team become more:

- Accountable: commitments, blockers, and follow-ups are visible enough to be owned.
- Responsible: each person can see what they planned, what they completed, what changed, and what needs support.
- Efficient: the system reduces repeated explanation, lost context, and manual end-of-day reporting.
- Effective: staff practice the habits of clear planning, disciplined execution, early communication, clean handoffs, and reflection.

## Habit Model

The workbook should reinforce a simple operating rhythm:

1. Start clear.
2. Work from priority.
3. Capture meaningful interruptions.
4. Raise risk early.
5. Ask for support before work stalls.
6. Close loops before the day ends.
7. Prepare tomorrow from real carryover.
8. Turn the day into a manager-ready report.

These habits are the product. The UI should make them easy to practice. The backend should make them measurable and coachable.

## Staff Experience

Staff-facing guidance should feel like an assistant, not a monitor. It should use short, practical prompts:

- Add your top three outcomes before the day starts.
- One must-close item is still open.
- Add a due window to this follow-up.
- Ask for support on the blocked vendor item.
- Confirm tomorrow ownership before close.

The system should avoid language that sounds punitive, accusatory, or overly personal. It should focus on the work and the next action.

## Manager Experience

Manager-facing summaries should provide accountability without micromanagement:

- What was planned?
- What was completed?
- What became blocked?
- What changed unexpectedly?
- Who asked for support?
- Which carryovers need ownership?
- Which patterns are forming?

Managers should see where help is needed and where staff are improving. The system should support coaching conversations, not replace them.

## What To Track

Track work signals that improve operations:

- Daily Focus outcomes
- Checklist completion and status
- Quick Updates
- Follow-ups and due windows
- Carryovers
- Support requests
- Report Seeds and reviewed draft decisions
- Task conversions
- Operating exceptions already surfaced by the app

## What Not To Track

Avoid data collection that does not improve execution:

- Keystroke-style monitoring
- Idle time surveillance
- Attempts to infer effort from screen presence
- Private notes not intended for operational use
- Staff comparison without context
- Punitive scoring labels

The workbook should measure operational clarity and follow-through, not human worth.

## Expansion Principle

The COO pilot should remain the proving ground. Once the model is trusted, the same architecture can be adopted across staff workspaces with role-specific prompts, permissions, and report outputs.
