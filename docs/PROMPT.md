# Context

The product requires Today’s Activity Feed to show real updates generated by actions inside the app, including generation, task creation, assignment changes, status changes, blockers, comments, and completion events.

The architecture defines `ActivityEvent` with these core fields:

- `id`
- `boardDayId`
- `actorUserId` optional for system events
- `taskId` optional
- `eventType`
- `message`
- `metadata` JSON
- `createdAt`

Activity events must be stored in the database and should not be inferred from UI-only state.

Recommended index:

- `ActivityEvent(boardDayId, createdAt)`

# Desired behavior

Implement an activity event persistence foundation that supports:

1. System events with no actor user.
2. User-generated events with an actor user.
3. Task-related events with an optional task relation.
4. Board-day-level events that do not require a task.
5. JSON metadata for structured event details.
6. Creation inside an existing Prisma transaction so later workflow mutations can write activity events atomically.
7. A typed set of event types that future tasks can reuse.

# Implementation guidance

## 1. Prisma schema

Add an `ActivityEvent` model to `prisma/schema.prisma`.

Use the project’s existing ID, timestamp, relation, and enum conventions. If the project already uses `cuid()`, `uuid()`, or other naming conventions, follow those exactly.

The model should include:

- Required `boardDayId`
- Optional `actorUserId`
- Optional `taskId`
- Required `eventType`
- Required `message`
- Optional or defaulted `metadata` JSON, depending on what Prisma/Postgres setup supports cleanly
- `createdAt` defaulting to now

Add relations to:

- `BoardDay`
- `User` as optional actor
- `Task` as optional related task

Use sensible `onDelete` behavior consistent with the rest of the schema. Prefer preserving audit history where possible. If existing schema conventions point clearly one way, follow those conventions.

Add indexes:

- `@@index([boardDayId, createdAt])`
- Add additional lightweight indexes only if clearly useful and consistent, such as `taskId` or `actorUserId`.
