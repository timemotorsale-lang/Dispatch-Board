# CRM Next — UX Specification

## Objective

Reduce cognitive load and clicks without reducing enterprise capability. Dominant workflow: `See attention item → understand why → Attend → execute → record outcome → next work`.

## Command Center

Header/global search; attention summary; dominant Needs Attention queue; My Work Today; appointments; compact pipeline; compact intelligence; manager-only team response/load when appropriate.

## Customer Workbench

Desktop target ~70/30.

### Main execution pane

Attention reason; next best action; current case/deal/workflow; execution controls; checklist/steps; recent activity; comments; completion/follow-up.

### Context rail

Customer snapshot; contact preference; vehicle/deal/relationship; BHPH/ownership context when relevant; open items; quick actions; risk/opportunity flags.

## Dynamic Overview

Prominence adapts to current situation (title issue, active shopper, service repair, payment attention) without hiding the complete record.

## Universal action bar

Call | Text | Email | Appointment | Task | More. Actions inherit customer and originating-record context where possible.

## Unified Timeline

Chronological events across communications, appointments, test drives, deal stages, sale/delivery, payments, service, titles/documents, cases, insurance, tasks, assignments, recommendations, escalations.

## Employee emphasis

My attention queue; appointments; customer tasks; next actions; quick execution.

## Manager emphasis

Organization-wide attention; unassigned work; overdue/SLA; stalled opportunities; escalations; team load; review.

## Mobile

Prioritize My Work/Needs Attention → customer snapshot → next action → universal actions → status/task update → recent activity. Secondary context collapses.

## Anti-patterns

No tab per domain; no KPI-heavy default page; no duplicate task UI; no requirement that staff know which module owns a problem; no buried Call/Text/Task; no unexplained raw priority scores; no new navigation for every capability.
